# 架构与业务范围

## 组件关系

用户小程序、商家后台、平台后台通过 HTTP API 访问同一 Go 服务；WebSocket 推送实时变化。Windows 桌面入口在本机托管已构建的前端，并反向代理 API；它不是独立的业务后端。

后端使用 MySQL 保存业务数据、Redis 支持缓存/锁/实时消息相关逻辑，通过 EMQX MQTT 与设备通信。设备协议实现主要位于 `backend/internal/device/`，访问控制和业务策略位于 handler、middleware、service 等目录。

## 值得展示的业务逻辑

- 门店与资源：平台维护门店、商家和产品模板；商家配置房间与资源。
- 预约与计费：查询可用时段、生成订单、保留计价信息，支持会员价快照。
- 余额与会员：充值/兑换、门店会员等级、折扣和有效期。
- 设备联动：设备绑定房间，用户控制受订单时间、门店权限和设备策略约束；定时任务负责提醒及按配置执行自动关闭。
- 运维能力：迁移脚本、健康接口、审计日志；生产监控脚本未直接复制进公开版。

## 边界

- 不包含官网源码和生产数据库。
- 不提供生产服务器入口、真实凭据或厂家设备账号。
- 自研 ESP 固件未纳入首版；厂家控制器接入仍需协议、账号和设备联调。
- 微信支付 V3 尚未完成；外部团购接口需要独立配置与联调。
